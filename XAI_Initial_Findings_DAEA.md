# Initial Findings

**Domain-Adaptive Explainable AI Framework for Big Data–Driven Decision Support Systems (DAEA / XAI-DSS)**

*Pre-submission due-diligence review against Scopus Q2 expectations. Lists publication blockers only (Critical → Major). Each item references concrete evidence from the manuscript tables/sections.*

| # | Issue Type | Impact | Issue Details | Recommendation |
|---|------------|--------|---------------|----------------|
| 1 | Experimental Design — Confounded core comparison | **Critical** | The headline CECI finding (AFR ρ = 0.61–0.72 vs. SFR ρ = 0.83–0.89) rests on exactly **one dataset per regime**. "Abstract vs. semantic" is fully confounded with dataset size (284,807 vs. 303), feature count (30 vs. 13), imbalance (577:1 vs. 1.1:1), domain, and LIME sampling. The causal claim that feature semantics drive consistency cannot be isolated; n = 1 per regime supports no generalisation. | Use ≥3–5 datasets per regime spanning varied sizes/dimensionality/balance; use a mixed-effects/regression design that isolates FSD from sample size and dimensionality, or hold them constant across regimes. |
| 2 | Experimental Design — Unvalidated domain classifier | **Critical** | DAEA "automatically classifies" the regime but is only shown on two datasets at opposite extremes (FSD 0.07 vs 0.92; DPS 0.93 vs 0.00). No held-out evaluation, no borderline/mixed cases, no threshold sensitivity analysis; thresholds appear hand-tuned to separate these two points. | Build a labelled multi-dataset corpus; report classifier accuracy/ROC on held-out datasets; include mixed/ambiguous cases; add threshold sensitivity analysis. |
| 3 | Experimental Design — No ablation of the central contribution | **Critical** | DAEA's regime-adaptive explanation is the primary novelty but is never compared to a non-adaptive baseline on any quantitative outcome. CECI depends only on SHAP/LIME, not on the regime adaptations, so no number demonstrates DAEA helps. "Usability"/"utility" gains are asserted, not measured. | Add a with/without-DAEA ablation and a measurable explanation-quality outcome (fidelity, sparsity, stability, or human-rated utility) the adaptation is meant to improve. |
| 4 | Reproducibility — DAEA scoring underspecified | **Critical** | The Domain Regime Score aggregates FSD, DPS, CIR, FICE, but no formula, weights, or thresholds are given. FSD relies on "ontological matching against domain knowledge bases" with no named ontology/procedure; FICE/DPS are undefined. The core mechanism is not reproducible. | Provide exact formulas for FSD/DPS/CIR/FICE, the DRS aggregation (weights) and thresholds, the knowledge base used, and pseudocode or released code. |
| 5 | Statistical Validity — No uncertainty/significance testing | **Major** | CECI is a single point ρ per cell — no CIs, no significance test of the AFR/SFR difference. Performance is described as "mean ± SD over folds," yet tables show only means (no SD). The central regime-difference claim lacks inferential support. | Report bootstrap CIs for all CECI values, formally test the AFR/SFR difference (n, p), and add SD/CIs to all performance and calibration tables. |
| 6 | Internal Consistency — CV vs. single split | **Major** | Methods state 5-fold CV (mean ± SD), but confusion matrices reconcile exactly to a single 70/30 split: XGBoost fraud (TP 116, FP 9, FN 32) reproduces precision 0.928 / recall 0.784 to 3 dp, and heart (78/91) reproduces accuracy 0.857. The "CV" tables may actually report one split. | State one consistent protocol; if CV, report per-fold dispersion and aggregate confusion matrices over folds (or clearly label as a representative split). |
| 7 | Internal Consistency — Misstated ECE range | **Major** | Abstract/Conclusion claim ECE reductions of "43.4%–65.3%," but recomputing every Table 5 row gives **56.6%** (LR-Fraud 0.0431→0.0187) to 65.3% (XGB-Fraud). No model yields 43.4%; the lower bound is unsupported. | Correct the range to match Table 5 (≈56.6–65.3%) and recheck all derived percentages. |
| 8 | Internal Consistency — Conflicting fraud feature count | **Major** | §1 states the fraud dataset has "13 features"; §3.3.1 and Table 1 state 30 (28 PCA + Amount + Time). The figures contradict. | Standardise to 30 (or specify the subset used) everywhere; verify all dataset descriptors. |
| 9 | Metric Validity — Wrong discrimination metric for extreme imbalance | **Major** | Under 577:1 imbalance, AUC-ROC (0.92–0.98 on fraud) is optimistic because true negatives dominate. The recommended rare-event metric, AUPRC / average precision, is absent. | Add AUPRC and precision–recall curves for fraud and foreground them over AUC-ROC. |
| 10 | Calibration Methodology — Unreliable on small clinical set | **Major** | For Heart (303), a 15% calibration hold-out ≈ 32 instances and test ≈ 91. Isotonic regression on ≈32 points overfits; 10-bin ECE on ≈91 instances (≈9/bin) is very noisy. Heart-domain calibration claims rest on fragile estimates. | Prefer Platt for small samples; use fewer/adaptive bins; report ECE bootstrap CIs; consider nested CV for calibration. |
| 11 | Novelty & Positioning — CECI overlaps prior agreement work | **Major** | CECI is a Spearman correlation between SHAP-global and aggregated LIME-local rankings. Explanation (dis)agreement/stability metrics are an established line of work; the "novel metric" claim is not positioned against or differentiated from it. | Cite/contrast prior explanation-(dis)agreement and stability metrics; state precisely what CECI adds. |
| 12 | Reproducibility — LIME aggregation/sampling undefined | **Major** | CECI uses "aggregated LIME local rankings" over 200 instances, but the aggregation rule (mean \|weight\|, sign handling, frequency, rank averaging), instance selection, and LIME's run-to-run instability are unspecified/unquantified. | Define the LIME→global aggregation and instance sampling precisely; report LIME variance across seeds and its propagation into CECI. |
| 13 | Overclaiming / Scope — "Big Data" framing not exercised | **Major** | Title/abstract/§1–2 foreground big data, the 5Vs, and Hadoop/Spark, but no distributed/streaming computation is done; 284,807 rows fit in memory and distributed work is deferred. Framing overstates demonstrated scope. | Either demonstrate scalability (distributed/streaming runtime/throughput) or substantially soften the big-data framing. |
| 14 | Overclaiming / Scope — "Domain-agnostic/automatic" contradicts ontology dependence | **Major** | DAEA is called domain-agnostic/automatic, yet FSD requires matching features to a domain ontology/knowledge base — presupposing domain knowledge and a curated resource per domain. It is unclear how this generalises to unseen domains. | Reconcile: explain semantic-density computation for an unseen domain without a hand-curated ontology, or reframe DAEA as semi-automatic/knowledge-assisted. |
| 15 | Experimental Design — Anecdotal validation | **Major** | SFR contrastive evidence is a single patient; "clinical benchmarking" is consistency with general AHA knowledge. No clinician review, user study, or systematic evaluation backs the utility claims. | Add expert (clinician/fraud-analyst) validation or a human-subjects usability study, or downgrade utility claims to illustrative. |
| 16 | Novelty & Positioning — Thin basis for "first/no prior work" | **Major** | Strong primacy claims rest on a 5-study comparison table with no systematic-review methodology, risking missed prior art. | Add a systematic-review protocol (search strings, databases, inclusion/exclusion, PRISMA flow) and broaden the comparator set. |
| 17 | Reproducibility — Missing artifacts and tuning protocol | **Major** | No code/data availability statement, no seeds, no library/version reporting; hyperparameters are fixed values with no described tuning/validation. | Provide a public repo, fixed seeds, software environment, and a documented hyperparameter-search protocol with validation evidence. |
